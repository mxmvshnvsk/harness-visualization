# Инструкции для агентов

## Постоянные требования автора

- Перед изменением кода прочитайте [стандарты кода](docs/code-style.md). Они обязательны для всей работы в репозитории, включая тесты.
- Главный критерий — код понятен человеку без объяснений автора. Не сокращайте запись ценой читаемости.
- Тела `if`, `else`, `for`, `while`, `switch`, `try`, `catch`, функций и callbacks с блоком всегда оформляйте на нескольких строках. Открывающая скобка завершает строку заголовка, тело начинается на следующей строке, закрывающая скобка начинается на новой строке. Допустимы `} else {` и `} catch (...) {`. Однострочные блоки запрещены.
- Используйте понятные имена, ранние возвраты и промежуточные переменные. Не вкладывайте тернарные операторы и не стройте длинные цепочки условий внутри JSX.
- Одна функция решает одну задачу. Ориентиры: не более 60 содержательных строк, сложность до 10, вложенность до трёх уровней и не более четырёх параметров. При превышении разбейте задачу по смыслу; не отключайте проверки ради прохождения линтера.
- Не считайте предупреждения о сложности нового кода приемлемым результатом. Исправляйте предупреждения, появившиеся из-за ваших изменений.
- Комментарии и документацию пишите по-русски; комментарии объясняют причины и ограничения. Сохраняйте принятую терминологию: prompt, reasoning, retrieval, тул, трейс, харнесс.

Этот раздел — проектная память о прямых требованиях Максима. Применяйте их в следующих сессиях.

## Проект и документация

Учебный харнесс для AI-агентов с визуализацией событий. Node.js 22.13+ (рекомендуется 24), строгий TypeScript, pnpm workspaces, Fastify, React.

- `packages/harness` — цикл агента, провайдеры моделей, конфигурация, тулы, события и ветвление.
- `packages/server` — HTTP API, запуск сессий, каталог трейсов и SSE.
- `packages/ui` — React-интерфейс, проекции событий и воспроизведение.
- `packages/mcp-server`, `packages/embeddings` — база знаний и embeddings.
- [Справочник](docs/reference.md), [формат событий](docs/events.md), [план](docs/plan.md), [справка интерфейса](docs/help/).

Файлы называйте по смыслу в `camelCase`; файлы классов и React-компонентов — в `PascalCase`. Для заимствованных идей и кода указывайте источник и соблюдайте лицензию.

## Совместимость и границы изменений

- Сохраняйте текущее поведение DeepSeek и чтение старых трейсов. Новые поля событий должны быть необязательными, если старые записи их не содержат.
- Авторство действий определяйте по событиям и их ID, с учётом `agentId`. Не приписывайте старым событиям модель из текущей конфигурации сервера.
- История ветки не является новым обращением к API. Не включайте общий префикс в стоимость продолжения.
- В браузерном коде используйте browser-safe экспорты пакетов. Корневой runtime-экспорт харнесса может подтянуть Node.js-зависимости; типы импортируйте через `import type`.
- Секреты из `.env` и конфигурации не выводите в логи, ответы API, трейсы и коммиты.
- Сетевые проверки моделей проводите через заглушки. Не вызывайте платные API ради проверки рефакторинга.
- Не редактируйте сгенерированные `dist`, рабочие папки и пользовательские трейсы как исходный код. Не удаляйте чужие изменения и артефакты.

## Проверка изменений

- `pnpm check` — типы, ESLint, Prettier, тесты и проверки арены.
- `pnpm build` — сборка всех пакетов, включая production-сборку интерфейса.
- Для затронутого поведения используйте содержательные регрессионные тесты. Для изменений интерфейса проверьте отображение в браузере.
- Проверяйте `git diff --check` и итоговый diff. Автоформатирование не заменяет чтение кода.
- Для отдельных Node-тестов сначала соберите пакеты. Запускайте тесты, у которых есть актуальные исходники: в `dist` могут оставаться файлы от удалённых модулей.
- В результате сообщите, что изменено, какие проверки прошли и какие существенные ограничения остались.

## Git

- Не создавайте коммит и не делайте push без запроса. Push делает Максим.
- Автор коммита — Maxim Vishnevsky; модель, внёсшая изменения, — соавтор через `Co-Authored-By`. Точное оформление сверяйте с историей.
- Сообщения коммитов — на английском. Один коммит соответствует одному законченному шагу.
- Для новых веток по умолчанию используйте префикс `codex/`.
