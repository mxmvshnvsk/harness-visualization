# Harness Visualization

Учебный харнесс для ИИ-агентов с визуализацией: видно, как вопрос превращается в контекст, что уходит в модель, какие тулы она зовёт и как работают MCP, RAG, память, скиллы, субагенты и управление контекстом. Модель — настоящая (DeepSeek или любой OpenAI-совместимый API), без заглушек.

## Установка и запуск

Нужны Node.js 24 (минимум 22.13, версия — в `.nvmrc`) и ключ выбранного провайдера: по умолчанию [DeepSeek API](https://platform.deepseek.com), также OpenRouter или OpenAI. Можно использовать локальный Ollama без ключа.

```bash
corepack enable          # pnpm нужной версии — из package.json
pnpm install
cp .env.example .env     # вписать ключ нужного провайдера
pnpm rag-index           # один раз: модель эмбеддингов и индекс базы знаний
pnpm dev                 # интерфейс — http://127.0.0.1:5173
```

`pnpm rag-index` скачивает с huggingface.co модель [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) (около 120 МБ) в `.cache/embeddings/` и считает векторы документов. Она нужна для поиска по смыслу, лаборатории RAG и проверки опоры ответа; без неё остальное работает.

Другие способы запуска:

```bash
pnpm serve               # собрать всё; сервер с интерфейсом — http://127.0.0.1:4317
pnpm chat "вопрос"       # агент в терминале, события — в консоль
```

В форме вопроса можно выбрать модель: DeepSeek по умолчанию, GLM или Claude через OpenRouter, GPT напрямую, Qwen локально. Ключи — в `.env`: `DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`. Пустой ключ не мешает открыть интерфейс; соответствующая модель недоступна для выбора. Для Qwen нужен запущенный Ollama с установленной `qwen3:8b`.

Модели задаются в `harness.config.json`, блоки `providers` и `models`. Старый блок `model` остаётся моделью по умолчанию; старый конфиг без реестра работает. CLI, ветки, Evals, лаборатории и оркестрация пока используют модель по умолчанию. Подробности — [реестр моделей](docs/reference.md#реестр-моделей).

Если DeepSeek или поисковик доступны только через прокси или VPN — раздел «Прокси и VPN» в [docs/reference.md](docs/reference.md).

## Стек

- **Язык и сборка:** TypeScript 6, Node.js 24, pnpm 10 (монорепозиторий), ESLint, Prettier, Vitest.
- **Харнесс** (`packages/harness`): цикл агента без SDK модели — запросы `fetch` к OpenAI-совместимому API, чтобы был виден ровно тот HTTP, что уходит; MCP-клиент `@modelcontextprotocol/client`; сеть через `undici` (маршруты: прокси или напрямую); zod для настроек и тулов.
- **MCP-сервер базы знаний** (`packages/mcp-server`): `@modelcontextprotocol/server`, 30 документов вымышленной компании «Кедр Софт», поиск по словам, по смыслу и гибридный.
- **Эмбеддинги** (`packages/embeddings`): `@huggingface/transformers`, локально, без внешних API.
- **Сервер** (`packages/server`): Fastify 5, поток событий в браузер (SSE).
- **Интерфейс** (`packages/ui`): React 19, Vite 8.

## Ключи поисковиков

Веб-поиск необязателен: без ключа тул `web_search` просто не появляется. Провайдер — `search.provider` в `harness.config.json` или флаг `--search yandex|tavily`.

- **Tavily** — зарегистрироваться на [app.tavily.com](https://app.tavily.com), скопировать API-ключ (`tvly-…`) в `TAVILY_API_KEY`. 1000 запросов в месяц бесплатно; из некоторых сетей — только через VPN.
- **Yandex Search API** — в [AI Studio](https://aistudio.yandex.ru): привязать платёжный аккаунт (Link billing account), нажать «Create API key» — вместе с ключом создаётся сервисный аккаунт с правами на Search API. Секрет ключа — в `YANDEX_SEARCH_API_KEY` (он показывается один раз), ID каталога (копируется из названия каталога вверху) — в `YANDEX_SEARCH_FOLDER_ID`. Платно, около 0,5 ₽ за поиск днём. Подробно — [Getting started with Yandex Search API](https://aistudio.yandex.ru/docs/en/search-api/quickstart/).

## Что есть

**Сессия агента.** Стартовый экран — вопрос агенту, сессии и трейсы. Агент «Кедр Софт» работает в песочнице `workspaces/demo/` с файловыми тулами, веб-поиском, MCP-сервером базы знаний, скиллами, памятью, субагентами и оркестрацией; опции — галочками в форме. Удаление файлов и рискованные действия харнесс спрашивает у вас по политике разрешений. Каждая сессия пишется в `traces/` и открывается снова.

**Плеер.** У открытой сессии или трейса — повтор с перемоткой и вкладки: «Поток» (харнесс изнутри, анимацией), «Инспектор» (шаги агента, запросы к модели, тулы, разрешения), «Код», «Контекст» (из чего состоял prompt на каждом шаге, кэш, обрезка и сжатие), «RAG», «MCP», «Агенты», «Ветки», «Скиллы и память», «Сырые события». От любого шага записанной сессии можно ответвиться: переиграть или подменить результат тула.

**Два режима** — переключатель в шапке:

- **Обучение** — со справкой «Что это?», вводными и выводами;
- **Исследование** — без учебного слоя; вместо инспектора — экран шагов: все запросы к модели таблицей, события харнесса между ними, снимок контекста перед каждым запросом с разницей с любым прошлым, сырые запрос и ответ с поиском по JSON. Клавиши `j` / `k` — шаг, `1`–`3` — вкладки.

**Лаборатории** (Лаборатории → …):

| Лаборатория  | Что в ней                                                                                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RAG          | как агент ищет в базе знаний: фрагменты, векторы, три поиска, проверка опоры ответа                                                                                              |
| MCP          | тул глазами модели, протокол, цена тулов, можно ли верить серверу                                                                                                                |
| Evals        | набор задач, несколько попыток, проверки кодом и судьёй, pass@k и pass^k по конфигурациям; прогон — `pnpm eval --set evals/<набор>.json`                                         |
| Выбор токена | ответ по токенам с вероятностями, температура на настоящих ответах, развилка — продолжить ответ с другого токена                                                                 |
| Код-арена    | агент правит проект и сам гоняет тесты, харнесс принимает работу скрытыми тестами; свободный режим — свой проект; код агента — в `node --permission` или, по настройке, в Docker |

В режиме «Исследование» учебных лабораторий RAG и MCP в списке нет.

Подробности о тулах, политике, MCP, поиске, настройках, сервере и командах — [docs/reference.md](docs/reference.md); решения и история этапов — [docs/plan.md](docs/plan.md); формат событий — [docs/events.md](docs/events.md).

## Трейсы других харнессов

Сессию Claude Code или OpenCode можно открыть в том же плеере: адаптер переводит запись в наши события. Ключи и домашняя папка в тексте маскируются при импорте; исходный файл никуда не уходит.

**Claude Code.** Запись сессии — `~/.claude/projects/<папка проекта>/<id>.jsonl`.

- В интерфейсе: «Сессии и трейсы» → «Открыть запись Claude Code или OpenCode…» → «Выбрать файл…» (папка скрытая — в окне выбора `Cmd+Shift+.`). Если в сессии были субагенты, появится кнопка «Добавить записи субагентов» — выберите все `agent-*.jsonl` из папки `<id>/subagents/`.
- В терминале — субагенты подхватятся сами:

  ```bash
  pnpm import-trace claude-code ~/.claude/projects/<папка>/<id>.jsonl
  ```

**OpenCode 2.x.** Экспорт — один JSON:

```bash
opencode session list                                    # id сессий в папке проекта
opencode session export <id> > traces/opencode-session.json
pnpm import-trace opencode traces/opencode-session.json
```

Если `opencode` не найден, вызовите его по полному пути (`which opencode` в терминале, где он работает): иначе `>` создаст пустой файл.

**Что видно и чего нет.** Видны вопросы, ответы модели с рассуждениями, вызовы и результаты тулов, токены и кэш, компакция, субагенты Claude Code, правки файлов во вкладке «Код» (у Claude Code — точный diff, у OpenCode — точный diff, если файл прочитан, иначе куски diff самого OpenCode). Тела запроса в таких записях нет: историю адаптер собирает заново, а system prompt и описания тулов того харнесса — остаток до настоящего input, одной частью. Решений политики и сетевых маршрутов нет, ветвиться от импорта нельзя. Всё это перечислено в шапке трейса чипом «нет в записи». Подробно — справка «Трейсы других харнессов» (`docs/help/imported-traces.md`).
