# Harness Visualization

Учебный харнесс для ИИ-агентов с визуализацией потока данных. Видно, как запрос пользователя превращается в контекст, что именно уходит в модель, какие тулы она просит вызвать и как работают MCP, RAG, память, скиллы и управление контекстом.

Работаем с настоящей моделью, без заглушек: смысл проекта в том, чтобы увидеть, что происходит на самом деле.

> **Статус:** этап 4 — файловые и веб-тулы, политика разрешений, MCP-сервер базы знаний. Этапы и принятые решения — в [docs/plan.md](docs/plan.md).

## Требования

- Node.js 22.13 или новее, рекомендуется 24 (указана в `.nvmrc`).
- pnpm: достаточно выполнить `corepack enable`, нужная версия pnpm указана в `package.json`.
- Ключ DeepSeek API — понадобится с этапа 1. Подойдёт и любой другой OpenAI-совместимый API.

## Быстрый старт

```bash
pnpm install
cp .env.example .env   # заполнить DEEPSEEK_API_KEY
pnpm chat "Сколько дней отпуска положено по регламенту? Запиши ответ в notes/vacation.md"
```

С флагом `--verbose` под каждой строкой печатается полное событие в JSON:

```bash
pnpm chat --verbose "вопрос"
```

Каждая сессия записывается в `traces/` — формат описан в [docs/events.md](docs/events.md).

## Песочница и тулы

Агент работает с файлами только в папке `workspace/`. При первом запуске она создаётся из примеров `examples/workspace/` — документов вымышленной компании «Кедр Софт». Выйти за пределы песочницы тулы не дают.

Песочница сохраняется между запусками: агент увидит заметки, которые написал в прошлых сессиях. Чтобы начать с чистого листа, добавьте флаг `--fresh` — папка будет пересоздана из примеров:

```bash
pnpm chat --fresh "вопрос"
```

| Тул            | Что делает                                                           |
| -------------- | -------------------------------------------------------------------- |
| `list_files`   | показывает файлы и папки                                             |
| `read_file`    | читает файл (длинные файлы обрезаются)                               |
| `search_files` | ищет текст во всех файлах без учёта регистра                         |
| `write_file`   | создаёт или перезаписывает файл                                      |
| `delete_file`  | удаляет файл — только с разрешения пользователя                      |
| `fetch_url`    | загружает страницу и возвращает её основной текст в Markdown         |
| `web_search`   | ищет в интернете через Yandex Search API или Tavily (если есть ключ) |

Лимит шагов агента за один ход — `agent.maxIterations` в `harness.config.json`.

**Политика разрешений.** Тулы только объявляют, что делают (`read`, `write`, `delete`, `network`) и с чем работают — пути и адреса. Решает харнесс по разделу `permissions` в `harness.config.json`, в таком порядке:

1. правила по аргументам (`rules`) — первое подходящее; в примере запрещены запись и удаление в `regulations/**`;
2. правило для конкретного тула (`tools`);
3. класс действия (`effects`): по умолчанию чтение, запись и сеть разрешены, удаление — спросить;
4. решение по умолчанию (`defaultDecision`) — для тулов, которые не объявили, что делают.

Если решение «спросить», харнесс спрашивает в терминале: «Разрешить? [y/N]». Каждое решение со всеми проверками записывается в трейс как `permission_evaluated`.

**Веб.** `fetch_url` загружает только http и https и по умолчанию не ходит на `localhost` и адреса локальной сети — чтобы модель не добралась до сервисов на вашем компьютере (`webFetch.allowPrivateNetwork` в конфиге).

**Поиск.** Провайдер выбирается в `harness.config.json` (`search.provider`) или флагом на один запуск:

```bash
pnpm chat --search yandex "вопрос"
pnpm chat --search tavily "вопрос"
```

| Провайдер         | Ключи в `.env`                                     | Условия                                                                                                                 |
| ----------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Yandex Search API | `YANDEX_SEARCH_API_KEY`, `YANDEX_SEARCH_FOLDER_ID` | [AI Studio](https://aistudio.yandex.ru): API-ключ и ID каталога, нужен платёжный аккаунт; около 0,5 ₽ за поиск днём     |
| Tavily            | `TAVILY_API_KEY`                                   | [app.tavily.com](https://app.tavily.com): 1000 запросов в месяц бесплатно; из некоторых сетей работает только через VPN |

Если ключей выбранного провайдера нет, `web_search` не регистрируется, а в консоли написано почему.

## MCP-сервер базы знаний

В `packages/mcp-server` — MCP-сервер с базой знаний «Кедр Софт»: 30 документов в `packages/mcp-server/data/` (регламенты, проекты, протоколы встреч, FAQ, разборы инцидентов, справочник сотрудников). Тулы сервера:

| Тул              | Что делает                                                      |
| ---------------- | --------------------------------------------------------------- |
| `search`         | ищет документы по словам с учётом окончаний, вес заголовка выше |
| `read_document`  | возвращает документ целиком, с датой и владельцем               |
| `list_documents` | показывает каталог документов, можно по типу                    |

Харнесс запускает серверы из раздела `mcpServers` в `harness.config.json` подпроцессами и говорит с ними по stdio. Модель видит их тулы с префиксом сервера: `kedr__search`. Сервер присылает инструкции — харнесс добавляет их в системный промпт.

Каждое сообщение JSON-RPC между харнессом и сервером записывается в трейс (`mcp_message`), строки из stderr сервера — тоже (`mcp_server_log`). В консоли видно рукопожатие: `initialize` → `notifications/initialized` → `tools/list`, а дальше `tools/call` на каждый вызов.

**Доверие к пометкам.** MCP-тул может пометить себя «только чтение» (`readOnlyHint`) — но пометку пишет автор сервера. Харнесс учитывает пометки, только если у сервера `trustAnnotations: true`; иначе тулы сервера получают `permissions.defaultDecision` — по умолчанию «спросить». Своему серверу мы доверяем, чужому — нет.

Ключи из `.env` сервер не получает: только базовые переменные (`PATH`, `HOME` и т. п.) и те, что перечислены в `environmentVariables`.

Запустить сервер отдельно, например для MCP Inspector: `node packages/mcp-server/dist/main.js` после `pnpm build`.

## Рассуждения (effort)

Модель может «подумать» перед ответом. Насколько усердно — задаёт уровень `off`, `low`, `high` или `max`. По умолчанию он берётся из `harness.config.json` (`defaultReasoningEffort`), а для одного запуска меняется флагом:

```bash
pnpm chat --effort off "вопрос"   # без рассуждений
pnpm chat --effort max "вопрос"   # максимум рассуждений
```

Сравните токены, время и стоимость на одном и том же вопросе: рассуждения — это токены выхода, самые дорогие.

## Ключ модели

Ключ можно положить в `.env` прямо (`DEEPSEEK_API_KEY=sk-...`), а на macOS — хранить в связке ключей и указать в `.env` только ссылку:

```bash
security add-generic-password -s harness-visualization-deepseek -a "$USER" -w
# в .env:
DEEPSEEK_API_KEY=keychain:harness-visualization-deepseek
```

Советуем завести отдельный ключ под этот проект и держать на балансе небольшую сумму.

## Модель и цены

Модель, адрес API и таблица цен — в `harness.config.json`. По умолчанию — `deepseek-flash`, рассуждения на уровне `high`. Как провайдер управляет рассуждениями, задаёт `reasoningStyle`: `deepseek` или `none`, если провайдер этого не умеет. Подойдёт любой OpenAI-совместимый API: поменяйте `baseUrl`, `model` и `apiKeyVariable`. Цены DeepSeek зависят от времени суток (пиковые и обычные часы), стоимость считается по времени запроса.

## Прокси и VPN

Если в окружении заданы `HTTPS_PROXY` или `HTTP_PROXY` (их часто выставляют VPN-клиенты и корпоративные сети), `pnpm chat` отправляет запросы через этот прокси: команда сама задаёт `NODE_USE_ENV_PROXY=1`, без которого встроенный `fetch` в Node ходит напрямую. В начале сессии видно, как идут запросы: «Сеть: напрямую» или «Сеть: через прокси …».
