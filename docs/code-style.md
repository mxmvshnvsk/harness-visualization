# Стандарты кода

Код в проекте пишется так, чтобы его можно было читать и понимать без автора. Большая часть правил проверяется автоматически: `pnpm check`.

## Имена

- Имена понятны человеку: `buildContextSegments`, `toolCallId`, `modelResponse`.
- Никаких шифров вроде `R1`, `F1-A1`, `tmp2`, никаких однобуквенных имён (исключение — координаты `x`, `y`).
- Переменные, функции и методы — `camelCase`; классы, типы и интерфейсы — `PascalCase`; неизменяемые константы — `UPPER_CASE`.
- Поля внешних API оставляем как в API (`finish_reason`, `tool_calls`), но переводим в наш формат на границе провайдера.

## Структура

- Одна функция — одна задача. Большие функции разбиваются на части, крупные части — на модули.
- Вложенность не глубже трёх уровней; если глубже — выносим в функцию.
- Не больше четырёх параметров у функции; если больше — передаём объект.
- Файлы и папки называются по смыслу в `camelCase`: `modelProvider.ts`, `contextManager/`.
- Файл, главное содержимое которого — класс или React-компонент, называется в `PascalCase`, как сам класс или компонент: `OpenAiCompatibleProvider.ts`, `ContextBar.tsx`.

## Без трюков

- Никаких битовых операций ради краткости: `~list.indexOf(item)` → `list.includes(item)`.
- Никаких неявных преобразований: `!!value` → `Boolean(value)`, `+text` → `Number(text)`.
- Никаких вложенных тернарных операторов — вместо них `if` или отдельная функция.
- Сравнение только через `===` и `!==`.

## Форматирование

- Отступ — 2 пробела.
- Строки заканчиваются `;`.
- Фигурные скобки вокруг тела обязательны, однострочных `if` и `for` нет.
- Одинарные кавычки, ширина строки — 100 символов.

## Стек

- Node.js 22.13+ (рекомендуется 24) + TypeScript (строгий режим), Fastify для сервера, React для интерфейса.
- Типы Node — от версии 22 (`@types/node@22`), чтобы случайно не использовать API, которых нет в минимальной версии.
- Монорепозиторий на pnpm workspaces.
- Без фреймворков для агентов: цикл агента пишем сами, чтобы всё было видно.

## Комментарии и документация

- На русском языке.
- Комментарий объясняет **почему**, а не **что** — «что» должно быть видно из имён.
- Учебные тексты справки лежат отдельно от кода, в `docs/help/`, с источниками и датой проверки.

## Чужие идеи и код

- Если берём чужую идею, алгоритм или реализацию, указываем автора и ссылку на источник: репозиторий, статью, страницу.
- В коде — комментарием рядом с заимствованием, в документации — в разделе «Источники». Скопированный код — только при совместимой лицензии, с указанием лицензии.
- Если реализация закрыта и взята только идея, так и пишем: «идея — …, реализация своя».

## Как это проверяется

| Правило                                   | Чем проверяется                                                                           |
| ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| Отступы, `;`, кавычки, перенос строк      | Prettier                                                                                  |
| Обязательные `{}`                         | ESLint `curly`                                                                            |
| Стиль имён                                | ESLint `@typescript-eslint/naming-convention`                                             |
| Однобуквенные имена                       | ESLint `id-length`                                                                        |
| Битовые операции и неявные преобразования | ESLint `no-bitwise`, `no-implicit-coercion`                                               |
| Вложенные тернарные операторы             | ESLint `no-nested-ternary`                                                                |
| Размер и сложность функций                | ESLint `max-lines-per-function`, `complexity`, `max-depth`, `max-params` — предупреждения |
| Типы                                      | TypeScript `strict`, `noUncheckedIndexedAccess`                                           |
