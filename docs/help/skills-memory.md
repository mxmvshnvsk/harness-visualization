# Скиллы, память и план

Модель ничего не помнит между запросами, а между сессиями — тем более. Всё, что агент «знает» сверх вопроса, харнесс кладёт в prompt сам. Три механизма — для разного.

## Скиллы

**Скилл** — инструкция для отдельной задачи: как отвечать по регламенту, как писать разбор инцидента. Папка в `skills/` с файлом `SKILL.md` (имя, описание и инструкция) и, если нужно, шаблонами и справками. Формат — как у [Agent Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) Anthropic.

Загрузка поэтапная — чтобы скилл не занимал prompt, пока не нужен:

1. в system prompt — только **каталог**: имя и описание каждого скилла, несколько десятков токенов;
2. подходит задача — модель загружает **инструкцию** тулом `load_skill`;
3. инструкция ссылается на шаблон — модель читает его `read_skill_file`.

Режимы: по выбору модели (по умолчанию), `always` — инструкция в prompt с самого начала, `manual` — в каталоге скилла нет, его загружает пользователь командой `/имя` в начале вопроса. На экране видно, какие скиллы модель видела в каталоге, но не выбрала: описание скилла — единственное, по чему она решает, поэтому плохое описание — частая причина, почему скилл «не срабатывает».

### Свои скиллы

Поиграть с моделью можно своими скиллами: папка с `SKILL.md` в `skills-custom/` (в git не попадает). Скиллы проекта — про «Кедр Софт» и есть только в демо-проекте, а свои — во всех режимах: с демо-проектом, без него и в Код-арене. В каталоге они помечены «свой»; что не прочиталось — ниже каталога с причиной. Пример — `examples/skills-custom/three-sentences`.

## Память

**Память** живёт между сессиями — папка `/memories` (в песочнице `memory/`). Модель работает с ней тулом `memory`, как в [memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) Anthropic: `view`, `create`, `str_replace`, `insert`, `delete`, `rename`. Главный файл — `memo.md`: харнесс кладёт его в system prompt в начале каждой сессии. Правки точечные — модель не переписывает файл целиком.

Память — это данные, которым модель потом доверяет как своим. Поэтому каждый путь проверяется (выйти из `/memories` нельзя), а удаление — с вопросом пользователю.

## План

Для задачи из нескольких шагов модель ведёт **план** тулом `update_progress`: цель и шаги со статусами — впереди, в работе, сделано, не выходит. Харнесс проверяет его (в работе — не больше одного шага) и пишет `progress.md`. План живёт в рамках сессии. Идея — как TodoWrite в Claude Code.

## Когда контекст сжимают

При [компакции](context-budget) прошлые ходы заменяет сводка — пересказ своими словами. Инструкции скиллов, план и изменённую память пересказывать нельзя: харнесс дописывает их к сводке как есть. А очистка старых результатов тулов инструкции скиллов не трогает вовсе.

На экране «Контекст» скиллы и память — отдельные части prompt: видно, сколько они стоят.
