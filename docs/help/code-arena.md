# Код-арена

Два режима: «Кедр Софт» — заготовленные задачи с приёмкой, и «Свободный» — песочница, где код пишут с агентом с нуля. В первом агент получает маленький проект и задачу, правит код в копии проекта и, если ему дали тул `run_tests`, сам запускает тесты. Когда он говорит «готово», харнесс принимает работу своими тестами — теми, которых агент не видел. Главный вопрос арены: **когда агент говорит «готово», это правда?**

## Два вида тестов

- **Видимые** (`test/`) — агент их читает и запускает. Это его обратная связь: «сломал или нет».
- **Скрытые** (`acceptance/`) — только у харнесса, запускаются после ответа. Это приёмка: то, что проверяет заказчик.

Приёмка запускает исходные видимые тесты — такими, какими они были до агента, — и скрытые. Дописывать свои тесты агенту можно, ослабить исходные — нет: запускаются не его правки, а исходники. Исключение — тесты, которые задача разрешает править (в `wrong-test` неверен сам тест).

## Вкладка «Код»

- **Файлы** — что агент прочитал и что поменял, diff каждого файла. Собирается из трейса: исходный текст — из результата `read_file`, новый — из аргументов `write_file`. Поэтому вкладка идёт за бегунком плеера и работает в повторе. Файл, записанный без чтения, — новый: исходного текста в трейсе нет.
- **Запуски тестов агентом** — когда он проверял себя и что упало.
- **Приёмка** — итог, исходные видимые тесты, скрытые тесты по одному.

## Что запускается на вашей машине

Тесты исполняют код, который написала модель. Поэтому `node --test` идёт с моделью разрешений Node (`--permission`): читать и писать — только в копии проекта, другие программы и воркеры запускать нельзя, окружение пустое — ключей DeepSeek и Tavily тестам не видно, таймаут 30 секунд. Сеть модель разрешений закрывает только с Node 25; на более старом Node в шапке прогона — «сеть открыта». Документация Node прямо называет это «ремнём безопасности»: от ошибок, а не от злоумышленника.

Крепче — контейнер Docker. В `harness.config.json`:

```json
"arena": {
  "sandbox": "docker",
  "docker": { "image": "node:24-alpine", "memory": "512m", "cpus": 1, "pidsLimit": 256 }
}
```

Тогда тесты и `run_node` идут в `docker run`: сети нет совсем (`--network none`) при любой версии Node; видна только копия проекта — она смонтирована как `/work`, остальная файловая система контейнера только для чтения; память, процессор и число процессов ограничены — бесконечный цикл или fork-бомба не положат машину; привилегии сброшены (`--cap-drop ALL`, `no-new-privileges`); процесс работает от вашего пользователя, поэтому файлы в копии остаются вашими. По таймауту харнесс убивает контейнер, а не только клиент `docker`. Цена — около секунды на каждый запуск и один раз скачать образ (`docker pull node:24-alpine`). Версию Node харнесс узнаёт у образа, она — в шапке прогона и в чипе «сеть закрыта». Нет Docker или он не запущен — лаборатория скажет это до запуска. Проверено на стенде: запрос в сеть — `EAI_AGAIN`, запись в `/etc` — `EROFS`, бесконечный цикл остановлен по таймауту вместе с контейнером.

## Настройки прогона

У арены свои пресет контекста и лимит шагов: `real` и 25. На пресете `demo` (12 тыс. токенов) и 10 шагах агент в прогонах 26.10.2026 терял вывод тестов, упирался в лимит и оставлял в копии временные скрипты. Тот режим остаётся экспонатом: `pnpm arena --task refactor --context demo --max-steps 10`.

## Свободный режим

Простая песочница — попробовать писать код с агентом. «Лаборатории → Код-арена → Свободный»:

- **Новый проект** — пустая папка с `package.json`, Node без зависимостей;
- **продолжить** — проект из прошлых сессий: они живут в `workspaces/arena/free/<имя>`;
- **начать с копии папки** — ваша папка копируется как есть, вместе с `node_modules`, без `.git`. Сети в арене нет, `npm install` не сработает — зависимости ставьте до копирования.

Задачу пишете словами, дальше — обычный диалог: «добавь флаг», «почини тест». Скрытых тестов нет, принимаете вы: diff во вкладке «Код», вывод тестов, программы агента. В терминале — `pnpm arena --project <имя> [--new | --copy <путь>] "что сделать"`.

## Программы агента: run_node

Агенту мало тестов: в прогонах 26.10.2026 он писал временные скрипты — сравнить старую и новую реализацию — и запустить их было нечем. Тул `run_node` запускает `node <файл> [аргументы]` в той же песочнице, что и тесты. **Каждый запуск харнесс спрашивает у вас** — в «Диалоге» или в терминале: это код модели на вашей машине. В `pnpm eval` спросить некого, поэтому там `run_node` нет. Изменить решение можно в `harness.config.json`: `permissions.tools.run_node`.

## Сравнить режимы

Один прогон ничего не доказывает: модель недетерминирована. Режимы арены сравнивают на k попытках, как вопросы в лаборатории evals:

```
pnpm eval --set evals/arena.json
pnpm eval --set evals/arena.json --configs blind,tests,tests-max,squeezed --trials 3
```

- `blind` — без `run_tests`: написал и сдал;
- `tests` — с `run_tests`: может проверять себя;
- `tests-max` — с `run_tests` и effort max;
- `squeezed` — с `run_tests`, но харнесс зажат: контекст `demo` и 10 шагов.

Набор `evals/arena.json` — regression: на DeepSeek он проходит почти весь и различает режимы только редкими провалами. Трудные задачи — отдельно, `evals/arena-capability.json`:

- `sick-pay` — кто платит за больничный: три правила регламента сразу, счётчик десяти дней доплаты на календарный год, больничный через Новый год;
- `sick-vacation` — заболел в отпуске: больничный до, после и на стыке отпуска, несколько листов, болезнь дольше отпуска;
- `new-year-vacation` — дан только симптом («отпуск через Новый год не оформить»), а ошибка глубже — в `calendar.js`; видимые тесты зелёные, починка «плюс 365 дней» проваливает високосный год.

```
pnpm eval --set evals/arena-capability.json --configs blind,tests,squeezed --trials 3
```

Проверки задач: «приёмка пройдена» и «не оставил лишних файлов» — новые файлы в копии вне `test/` (временные скрипты); у `wrong-test` ещё судья — объяснил ли агент, что неверен тест, а не код. Итоги — в «Лаборатории Evals», вкладка «Прогон».
