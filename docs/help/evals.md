# Evals

**Eval** — тест для поведения агента: набор задач, несколько попыток на каждую и проверки, по которым видно, справился ли агент. Нужен, чтобы после изменения — инструкции, способа поиска, тула, модели — знать, что стало лучше и что сломалось, а не «вроде стало лучше».

## Из чего состоит

- **Задача (task)** — вопрос агенту и критерий успеха. Берут из настоящих провалов: 20–50 простых задач — уже хорошее начало.
- **Попытка (trial)** — одна сессия агента над задачей. Модель отвечает по-разному, поэтому задачу гоняют k раз.
- **Трейс (transcript)** — полная запись попытки. Проверяют не только ответ, но и путь: какие тулы, сколько шагов, что прочитано.
- **Проверки (graders)** — кодом (быстро и воспроизводимо, но хрупко: «28» найдётся, «двадцать восемь» — нет), моделью-судьёй (понимает смысл, но сам ошибается) и человеком (эталон, но дорого).

## pass@k и pass^k

- **pass@k** — задача решена хоть раз из k попыток: «умеет ли агент».
- **pass^k** — решена во всех k: «можно ли на него положиться». Для агента, который отвечает людям, важнее второе.

При k = 1 они совпадают, с ростом k расходятся: pass@k растёт, pass^k падает. Разница между ними — насколько агент непостоянен.

## Как у нас

`pnpm run eval` гоняет набор `evals/kedr.json` — 12 задач из уроков стенда — по 3 попытки в конфигурациях поиска `tool` и `auto`. Каждая попытка — обычная сессия со своим трейсом; конфигурации чередуются, чтобы прогретый кэш доставался всем. Итог попытки — ✓, ✗ или «?»: провалов нет, но судья не вынес вердикта. «?» не засчитывается: «не знаем» — не «прошла». Отчёт — в `traces/evals/`, его показывает вкладка «Прогон».

Судья видит вопрос, рубрику и ответ, но не документы: «не выдумал ли агент» проверяет `pnpm check-grounding`.

## Сравнение моделей

Запуск с несколькими моделями реестра:

```sh
pnpm eval --models default,glm-4.6 --configs tool --trials 3 --judge-model default
```

Каждая модель получает те же задачи и выбранные конфигурации харнесса. Для одной модели можно использовать `--model qwen-local`; без этих флагов поведение старой команды сохраняется. Имена моделей и провайдеров, API ID и effort видны в итогах, матрице, выбранной попытке и сравнении отчётов.

`--effort high` задаёт один уровень для всех участников. Без него действует effort конфигурации арены либо выбранной модели. Неподдерживаемый уровень, неизвестная модель или отсутствующий ключ останавливают запуск до первого запроса.

Судья фиксирован для всего прогона и выбирается отдельно через `--judge-model` (по умолчанию `default`). Он работает с effort `off`: модель, которая не поддерживает этот уровень, не подходит для текущего судьи. Флаг `--no-judge` отключает его; с ним можно запустить локальную модель без ключа DeepSeek. Цена судьи остаётся в его отдельном трейсе, а цены попыток — в строках конфигураций.

Отчёт сохраняет снимки моделей и фактические имена в ответах API. Изменение реестра после прогона не переписывает прошлые результаты. Старые отчёты используют записанные в них общие модель и effort; неизвестная модель судьи не подставляется из текущего конфига.

Чередование попыток не уравнивает кэши разных моделей и провайдеров. При сравнении цены учитывайте их прогрев и неизвестные тарифы. Изменение модели судьи между прогонами также видно в сравнении.
