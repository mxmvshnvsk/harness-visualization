# Бюджет prompt

Модель ничего не помнит: каждый запрос несёт весь контекст заново — system prompt, описания тулов, весь диалог и результаты тулов. Поэтому с каждым шагом и каждым вопросом запрос растёт. **Бюджет** — сколько харнесс отводит prompt; лимит задаёт харнесс, а не провайдер.

**Пресеты** (`context.preset` в `harness.config.json`):

- `demo` — 12 000 токенов: место кончится на 3–4-м вопросе диалога;
- `stress` — 6 000: уже на первом вопросе с поиском;
- `real` — 1 000 000, окно `deepseek-flash`.

**Порог** — 80 % лимита (`context.thresholdPercent`): с него харнесс начнёт освобождать место — обрезать большие результаты тулов, удалять старые, сжимать историю в сводку. Пока бюджет только показан.

## Как считается разбивка

Провайдер возвращает только итог — `usage.inputTokens`, и то после ответа. Из чего он сложился, харнесс **оценивает** сам, до отправки:

> токенов ≈ символы JSON части запроса ÷ 3,24

Части: системные сообщения, описания тулов (`tools`), диалог (вопросы и ответы модели вместе с просьбами вызвать тулы), результаты тулов (сообщения с ролью `tool`).

Коэффициент 3,24 подобран по 282 запросам из трейсов автора: у каждого есть точный `inputTokens`. Медианная погрешность — 2,6 %, худшая — 18,5 %. Отдельные коэффициенты для кириллицы и остального текста точнее не стали. В инспекторе рядом с оценкой — точное число из ответа и насколько оценка ошиблась.

## Почему оценка, а не точный счёт

Модель видит не символы, а токены — куски текста по словарю токенизатора. На английском один токен — около 3–4 символов, на русском и в JSON — иначе. Точно считает только настоящий токенизатор модели. У DeepSeek он есть офлайн: ориентиры и архив — на странице [Token & Token Usage](https://api-docs.deepseek.com/quick_start/token_usage) (там же: 1 английский символ ≈ 0,3 токена, 1 китайский ≈ 0,6). Харнесс его не подключает: это тяжёлая зависимость и словарь на мегабайты, а итог провайдер и так отдаёт точно.
