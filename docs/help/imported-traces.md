# Трейсы других харнессов

Плеер, инспектор и «Диалог» умеют показывать не только наши прогоны. **Адаптер** переводит запись чужого харнесса в наши события — и сессию Claude Code или OpenCode можно разобрать по шагам так же, как сессию нашего агента с DeepSeek.

## Как открыть

- В интерфейсе — «Сессии и трейсы» → «Открыть трейс другого харнесса…». Формат определится сам; трейс сохранится в `traces/` с чипом «Claude Code» или «OpenCode».
- В терминале — `pnpm import-trace claude-code <файл>.jsonl`, `pnpm import-trace opencode session.json` или `pnpm import-trace auto <файл>`.

**OpenCode 2.x** — экспорт сессии: `opencode session list` в папке проекта покажет id, `opencode session export` выгрузит JSON. В старых версиях команда называлась `opencode export`. Экспорт без маскировки: в нём всё, что видела модель, — просмотрите файл, прежде чем им делиться.

**Claude Code** — записи лежат в `~/.claude/projects/<папка проекта>/<id сессии>.jsonl`. Папка скрытая: в окне выбора файла на Mac — Cmd+Shift+.

## Что переводится

- Вопросы пользователя.
- Ответы модели: рассуждение, текст, вызовы тулов. Claude Code пишет один ответ несколькими записями — по записи на блок; адаптер собирает их по `message.id`.
- Результаты тулов, ошибки тулов.
- Токены и кэш. У Anthropic вход делится на три счётчика: без кэша, прочитано из кэша, записано в кэш. У нас «попадание» — прочитанное, «промах» — остальное.
- Компакция истории: размер до и после и сама сводка.
- Субагенты Claude Code. Claude Code 2.1 пишет их отдельно от главной записи: рядом с `<id>.jsonl` — папка `<id>/subagents/` с файлами `agent-*.jsonl`. Строки субагента помечены `isSidechain` и `agentId`, а результат тула `Agent` у главного агента несёт тот же `agentId` — по нему адаптер ставит работу субагента между поручением и отчётом, как у наших субагентов: вкладка «Агенты», дорожки на таймлайне, у каждого своя история в «Контексте». `pnpm import-trace` подхватывает папку `subagents/` сам. В интерфейсе окно выбора не даёт взять файлы из двух папок, поэтому после импорта главной записи появится кнопка «Добавить записи субагентов» — выберите все `agent-*.jsonl`, и запись переведётся заново вместе с ними.
- Служебные вставки `<system-reminder>`, которые Claude Code дописывает в сообщение пользователя (дата, контекст), в вопросе убраны: вопросом они не являются. Модель их видела — их токены остаются в восстановленном остатке «Контекста».
- Что агент сделал с файлами — для вкладки «Код». Тулы у каждого харнесса свои, поэтому адаптер переводит их в одно из трёх: прочитал, записал, поправил фрагмент. Claude Code рядом с результатом тула пишет, что видел его интерфейс: у `Read` — текст файла, у `Edit` и `Write` — файл до правки, поэтому diff точный. OpenCode отдаёт аргументы и текст результата: `read` — строки с номерами (их адаптер снимает), `edit` — фрагмент «было → стало», который накладывается на последний прочитанный текст. К `edit` OpenCode прикладывает и diff правки (`metadata.files[].patch`): если файл не читали или прочитали кусок, правка показана кусками этого diff — с соседними строками, а не голой заменой. Что агент делал с файлами через shell (`sed`, `cat >`), адаптер не видит. Пути — от папки проекта.

## OpenCode

Экспорт устроен проще записи Claude Code: сведения о сессии и сообщения по порядку. Ответ модели — одно сообщение с блоками: рассуждение, текст, тулы; результат тула лежит прямо в его блоке — OpenCode выполняет тулы, пока ответ ещё пишется. Цену шага OpenCode пишет сам, одним числом: она есть в инспекторе, но без разбивки на кэш и вывод. Правка `edit` проверена на настоящем экспорте OpenCode 2.1.4; `write` разобран по тем же полям, но на настоящей записи ещё не встречался.

## Чего в записи нет

Интерфейс показывает это в шапке, а не пустотой:

- **Тело запроса.** В запись попадают только ответы. Историю — вопросы, ответы модели, вызовы и результаты тулов — адаптер собирает заново, и вкладка «Контекст» показывает, что было в prompt на каждом шаге. А system prompt и описания тулов того харнесса восстановить нельзя: их размер — остаток между настоящим input из usage и оценкой истории, во вкладке он идёт частью system с пометкой. На экспорте OpenCode автора этот остаток держится около 5–7 тыс. токенов на каждом шаге — столько стоит «налог» system prompt и меню тулов. Лимита контекстного окна в записи тоже нет. Ветвиться от импорта нельзя: тело собрано заново, а не записано.
- **Разрешения и сеть.** Claude Code не пишет решения политики и маршруты запросов.
- **Цена.** Тарифы Anthropic в адаптере не заданы.
- **Субагенты OpenCode** — отдельные сессии, их экспортируют отдельно. У субагентов Claude Code в записи нет списка их тулов и лимита шагов.

## Осторожно

- Форматы не документированы: запись Claude Code и экспорт OpenCode меняются от версии к версии (адаптер OpenCode сделан по экспорту версии 2.1.4). Адаптер берёт только устойчивое ядро — сообщения в формате Anthropic Messages API. Описания формата — только от сообщества.
- В результаты тулов попадает всё, что прочитала модель, — в том числе `.env`. Адаптер маскирует ключи (`sk-…`, `tvly-…`, `ghp_…`, `Bearer …`, `API_KEY=…`) и домашнюю папку, но перед тем как делиться трейсом, просмотрите его.
